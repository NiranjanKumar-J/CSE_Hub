## DBMS (Database Management System)

A DBMS is a software system that allows users to define, create, store, retrieve, and manage data in a
database efficiently. It also provides security, integrity, and concurrency control.

## DBMS Architecture

DBMS architecture refers to the structural design of a DBMS that explains how users, applications, and the
database interact. 

Common types are:
* **One-tier architecture -** User directly interacts with the database.
* **Two-tier architecture -** Client communicates directly with the database server.
* **Three-tier architecture -** Client - Application Server - Database Server (most widely used).

The **two** main functional components are:

* Storage Manager
* Query Processor

## Storage Manager :-

The Storage Manager is the interface between the low-level data stored in the database (disk) and the application programs/queries.

It consists of **four** key components:

**1) Authorization and Integrity Manager:**
* **Security:** Checks if the user has the authority (permission) to access the data.
* **Integrity:** Ensures that the data stored satisfies all integrity constraints (rules).

**2) Transaction Manager:**
* **Manages concurrency control**, allowing multiple users to access the database simultaneously without conflict.

**3) File Manager:**
* Handles the data structures used to represent information stored on the disk.

**4) Buffer Manager:**
* Responsible for fetching data from the disk into **Main Memory (RAM)**.


**Physical Storage Structures:**
* Data Files
* Data Dictionary
* Indices

## 2. Query Processor

The Query Processor simplifies access to data by translating high-level user queries (like SQL) into efficient low-level machine operations.

It consists of **three** key components:

**1) DDL Interpreter:**
* Interprets DDL (Data Definition Language) statements.
* Records the schema details in the **Data Dictionary**.

**2) DML Compiler:**
* Translates DML (Data Manipulation Language) queries into an evaluation plan (low-level instructions).

**3) Query Evaluation Engine:**
* Executes the low-level instructions generated by the DML compiler to produce the final result.

## 3. Database Architecture (Client/Server)

This explains how users connect to the database system over a network.

**A) One-Tire Architecture:**
* The users can directly communicate with the Database Server.

![My Image](https://media.geeksforgeeks.org/wp-content/uploads/20260117150413249662/single_tier_architecture.webp)

**B) Two-Tier Architecture:**
* The client communicates directly with the Database Server using APIs like ODBC or JDBC.

![My Image](https://media.geeksforgeeks.org/wp-content/uploads/20250108093805302915/2_tier.webp)

**C) Three-Tier Architecture:**
* *Client (Tier 1):* Acts only as a front-end interface (like a web form). It does not talk to the DB directly.
* *Application Server (Tier 2):* Contains the "Business Logic". It receives requests from the client and processes them.
* *Database Server (Tier 3):* The Application Server connects here to fetch data.

![My Image](https://media.geeksforgeeks.org/wp-content/uploads/20250108093901256398/3_tier.webp)

## ✅ Conclusion

Database System Architecture provides a structured way to design and manage databases efficiently. The three-level architecture ensures abstraction and independence, while multi-tier architectures improve scalability, security, and performance in real-world applications.
